# S7comm (Siemens, port 102)

Siemens S7comm rides on top of TPKT (RFC 1006) + COTP (ISO 8073).
S7-300 / S7-400 / S7-1200 / S7-1500 all speak variants on port 102.
The protocol does not authenticate by default; newer firmwares add
"access protection" but many production PLCs leave it disabled.

## Probe

1. Open TCP to port 102.
2. Send a TPKT-wrapped COTP Connection Request with SrcTSAP 0x0100
   and DstTSAP 0x0102 (rack 0, slot 2 — the S7-300/400 default).
3. Read the COTP Connection Confirm. A CC response indicates an S7
   family PLC; capability score bumps from 30 → 70.

A COTP Disconnect Request or silent close means the target is
either not S7 or uses a different TSAP pair.

## CPU protection-level probe (active recon, read-only)

`elsereno s7 probe-protection --target host:102` goes past the
fingerprint: it reads whether the CPU accepts writes/control without
a password, the root misconfiguration behind "anyone can stop the
PLC / change a tag". It drives the full handshake and reads one
diagnostic list:

```
COTP Connection Request -> Setup Communication -> Read SZL 0x0132 index 4
```

SZL 0x0132 index 4 (from SFC51 RDSYSST) carries the CPU's protection
configuration. The probe reports:

- **Effective (real) protection level**: 1 = no password (access via
  the key switch only), 2 = write-protected (write needs a password),
  3 = read+write protected. Level 1 (or 0/undefined) is the exposure:
  a stranger can write tags or control the PLC.
- **Parameterised level** (from the hardware config) and **key-switch
  level**, for context.
- **Mode selector** (bart_sch): RUN / RUN-P / STOP / MRES. RUN-P means
  programming is enabled at the switch.

It is strictly read-only: it reads the protection SZL, it never
writes, controls or stops the PLC.

The wire (`internal/protocols/s7/wire/setup.go`, `szl.go`) and the
client (`internal/protocols/s7/protectionprobe.go`) are validated
**byte for byte against a real captured S7-300 session**
(ITI/ICS-Security-Tools `s7comm_reading_plc_status.pcap`): the Setup
handshake, the Read SZL request, and the protection response all match
the real bytes, cross-checked against the Wireshark S7comm dissector
(`packet-s7comm_szl_ids.c`). Idea from the OT-exposure batch inspired
by the researcher Christopher D.'s `chrisdinozzi/opcua-recon`.

## Proxy policy (default build)

Every TPKT envelope is parsed; the COTP PDU type + S7 function byte
are extracted. CategoryRead functions (Setup Communication 0xF0,
Read Var 0x04) forward; everything else short-circuits to an S7
AckData with error class 0x85 ("Function not allowed") and error
code 0x01. The PDU Ref is echoed for correlation.

## Writes (`-tags offensive`)

`offensive/write/s7` implements:

| Op             | S7 function   | Notes                                  |
|----------------|---------------|----------------------------------------|
| `write_var`    | 0x05          | Byte / Char transport, ≤200-byte cap   |
| `plc_stop`     | 0x29          | Trailing "P_PROGRAM" ident             |
| `plc_restart`  | 0x28          | Cold restart                           |

PLC Stop is functionally a safety event; always triple-confirm
explicitly with the operator.

## Scope

Siemens S7 family — S7-200, S7-300, S7-400, S7-1200, S7-1500, as well
as S7-compatible clones (Vipa, others). The `Setup Communication`
response carries PLC type + firmware identifiers.
