# Snapshot — v2.46.0: sparkline bucket click → drill into /runs

Single-chunk cycle. Closes v2.22 carryover. v2.45 added the
/runs?since=&until= filter; v2.46 wires sparkline buckets
to use it. Click any bucket → that bucket's [since, until]
window opens in the runs view.

## UX

  - Hovering a bucket: tooltip ends with "· click to drill".
  - Clicking a bucket:
    1. Sparkline view closes.
    2. Runs view opens with the bucket's window pre-applied.
    3. Subtitle shows the active filter + a "clear filter"
       button.
  - Closing the runs view auto-clears the filter so the
    next open is unfiltered.

## JS state

  - `sparklineBucketGrain` (hour/day/week) — set in
    reloadSparkline so the click handler can compute the
    bucket step (1h / 24h / 7d).
  - `runsFilterSince` / `runsFilterUntil` — set by
    drillSparklineBucket, consumed by fetchRunsPage.
  - `clearRunsFilter` — operator escape hatch.

## Implementation detail

  - Bucket rects get `style="cursor:pointer;"` + `onclick`
    + `data-since`/`data-until` attributes.
  - `until` = `bucket_start + step - 1ms` (inclusive RFC3339
    that doesn't bleed into the next bucket).

## Window exposure

  - `window.drillSparklineBucket(since, until)`
  - `window.clearRunsFilter()`

## Honest scope

  - Filter window supersedes the cursor pagination (v2.45
    handler behaviour); "Load more" inside a filter is
    disabled — operator gets the first 50 in the window.
    Paginate-within-window deferred (vNext from v2.45).

## Build sizes

Unchanged. JS-only.

Adds ~80 LoC net (mostly in renderSparklineSVG + openRunsView).
