# Snapshot — v2.56.0: cmd_tui ReplayControl wiring

Single-chunk cycle. Closes v2.53 carryover. v2.53 shipped
the `feeds.ReplayControl` + `tui.ReplayController`
interface + key handlers (space/[/]); v2.56 wires
`cmd_tui.go` so an operator running
`elsereno tui --replay …` actually gets the controls
without library callers needing to construct anything.

## Plumbing

`pickFeed` (replay branch):

```go
ctl := feeds.NewReplayControl(a.rate)
return tui.ModeReplay, feeds.Replay{
    Path: a.replayPath, Rate: a.rate, Control: ctl,
}, nil
```

`RunE`:

```go
if rep, ok := feed.(feeds.Replay); ok && rep.Control != nil {
    runOpts.ReplayCtl = rep.Control
}
```

The Replay struct + Model both hold the same `*ReplayControl`
pointer; key handler mutates atomic state that the feed
goroutine reads before each line.

## CLI help

`elsereno tui --help` now documents the v2.53 keys:

```
v2.53+ replay controls (only when --replay is set):
  space    pause / resume playback
  [        halve playback rate (uncapped → 1.0/s)
  ]        double playback rate (no-op when uncapped)
Audit pane shows live "(replay: paused)" / "(replay rate:
N.NN/s)" feedback.
```

## Honest scope

  - Non-replay modes (--feed, --watch, --input) still
    leave runOpts.ReplayCtl nil — the keys no-op there.
    Future: add similar Control to feeds.Stdin for live
    stdin pacing if anyone asks.
  - No regression test that simulates an actual key
    press → unpause sequence end-to-end; that needs
    teatest harness work which is its own cycle. The
    underlying ReplayControl is covered by the v2.53
    unit tests.
