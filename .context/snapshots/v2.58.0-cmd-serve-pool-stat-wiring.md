# Snapshot — v2.58.0: cmd_serve PoolStat adapter

Single-chunk cycle. Closes v2.52 + v2.55 carryover.
`/api/v1/health/pool` (v2.52 endpoint) + Prometheus
`elsereno_pool_*` metrics (v2.55) both relied on a
PoolStatter being injected. v2.58 supplies the adapter
that turns the live `*pgxpool.Pool` into the local
`handlers.PoolStat` shape.

## Plumbing

`internal/web/server.go`:

```go
type Options struct {
    ...
    PoolStatter handlers.PoolStatter  // v2.58+
}
```

Forwarded into `APIV1Deps.PoolStatter` in `NewServer`.

`cmd/elsereno/cmd_serve.go`:

```go
type pgxpoolStatter struct{ pool *pgxpool.Pool }

func (p *pgxpoolStatter) Stat() *handlers.PoolStat {
    s := p.pool.Stat()
    return &handlers.PoolStat{
        AcquireCount: s.AcquireCount(),
        AcquireDuration: s.AcquireDuration(),
        AcquiredConns: s.AcquiredConns(),
        // ... all 12 fields
    }
}
```

`buildWebOptions` constructs the shim when `pool != nil`
and assigns to `out.PoolStatter`. Memory-mode deployments
still get a nil PoolStatter → endpoint returns 503
cleanly.

## Result

  - `curl http://127.0.0.1:8787/api/v1/health/pool` now
    returns live pgxpool stats on db-mode deployments.
  - Prometheus collector (registered in a separate cycle)
    can scrape via the same shim.

## Honest scope

  - No Prometheus collector registration yet in cmd_serve
    (that's v2.59 if we want the metrics endpoint, or
    operator picks Grafana-via-JSON-endpoint).

Unchanged.
