# Snapshot — v2.51.0: TUI replay status progress

Single-chunk cycle. Long captures (10k+ findings) leave the
operator wondering "am I at line 100 or 9000?". v2.51 adds
periodic progress emissions so the audit pane shows
playback position.

## New message type

```go
type ReplayStatusMsg struct {
    Path      string  // capture file
    LineCount int64   // emitted so far
    Rate      float64 // configured replay rate (0 = uncapped)
}
```

## Replay extended

`feeds.Replay.StatusEvery int` (defaults to 100; set to -1
to disable). Every N FindingMsg / AuditMsg emissions, the
feed dispatches a ReplayStatusMsg.

## Update handler

New case in `Model.Update`:

```
(replay progress: 500 lines @ 5.0/s · /captures/incident.ndjson)
```

Renders as a standard audit-pane line — operators get
visible playback heartbeat without separate UI elements.

## Tests (+2)

  - TestReplay_StatusEmission: 5 lines + StatusEvery=2 →
    2 ReplayStatusMsg emissions (at counts 2 + 4).
  - TestReplay_StatusDisabled: StatusEvery=-1 → 0
    emissions.

## Honest scope

  - No total-line-count in status (would need a 2-pass
    read or upfront `wc -l`). Operator sees absolute
    count + can compare to known capture size.
  - No mid-playback rate change (`Replay.Rate` immutable
    after start). Pause/step bindings vNext.
