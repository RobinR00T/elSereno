# Snapshot — v2.61.0: sandbox profile introspection + ProfileScan test gap closure

Single-chunk cycle. Tightens the v1.50 macOS sandbox
implementation along three independent axes that piled up
since the original ship: a regression that silently dropped
ProfileScan (added in v2.32) from the darwin tests, a
half-baked error path when sandbox_init returns rc≠0 with
no errbuf, and the lack of an introspection accessor that
ops tooling could call to inspect a profile before
applying it.

## Why now

v2.61 is the "refinement" beat the v2.41/v2.40 cycles
foreshadowed for the macOS sandbox surface. Three concrete
gaps were carried forward:

  1. **Test gap (v2.32 regression)**: when v2.32 added
     ProfileScan, the v1.50 darwin tests kept their
     hand-coded `[]Profile{ProfileExploit, ProfileHarvest,
     ProfileDial}` slice and silently skipped ProfileScan.
     Both `TestDarwinProfileSchemesPresent` and
     `TestDarwinAllProfilesHaveDistinctSchemes` had this
     bug for 29 cycles. A regression that dropped or
     copy-pasted the scan scheme would have shipped green.
  2. **Error message blank**: `sandbox_init: %s (rc=%d)`
     with `errMsg = ""` produces "sandbox_init:  (rc=22)"
     — a double-space + zero diagnostic when the kernel
     doesn't populate errbuf (observed on macOS 14 hosts
     with EINVAL). Audit log readers had no signal.
  3. **No introspection surface**: SBX profiles were
     unreachable from outside the cgo `Load()` path.
     Future `sandbox introspect` CLI verb (vNext) had no
     scoping to attach to.

## What's new

### `Profiles() []Profile`

Single source of truth in `sandbox.go`. Returns the 4
canonical profile values in declaration order. `Valid()`
delegates to this so the two stay in sync by construction.
All call sites that previously iterated a hand-listed slice
now iterate `Profiles()` — the regression that caused the
v2.32 test gap is structurally impossible going forward.

### `SchemeFor(p Profile) (string, bool)` (darwin+cgo only)

Public accessor that returns the .sb Scheme string without
applying the sandbox. Operators / audit tooling can inspect
the effective policy before forking a subprocess. Returns
("", false) for unknown profiles. Only available on the
darwin+cgo build path — schemes are macOS-specific (Linux
seccomp-bpf has its own binary BPF blob).

### Hardened error path

`Load()` now substitutes "kernel did not provide a reason"
when `errbuf` is nil/empty on rc≠0, and the success
`Reason` field now includes the profile name
(`"macOS sandbox_init(3) profile=exploit applied"`).
Audit log readers can distinguish exploit-applied vs
harvest-applied without parsing the parent LoadResult.

## Test coverage

  - **TestProfilesEnumerationStable** (new, shared): pins
    Profiles() to {exploit, harvest, dial, scan} in
    declaration order. Adding a new profile requires
    updating this test alongside sandbox.go.
  - **TestDarwinProfileSchemesPresent** (rewritten):
    iterates Profiles() — automatic ProfileScan coverage.
  - **TestDarwinAllProfilesHaveDistinctSchemes**
    (rewritten): N×N pair distinctness via Profiles().
    Adds ProfileScan-specific shape assertions:
    `(allow network*)` + `(deny file-write*)`.
  - **TestDarwinSchemeFor** (new): fences SchemeFor API
    shape for downstream callers.

All 6 sandbox tests pass on both cgo and non-cgo paths.

## Build sizes

Unchanged. The added Profiles()/SchemeFor() symbols are
~12 LoC in the offensive build; the cgo wrapper grew by
the same ~8 LoC for the error-message hardening. The
default build is untouched.

## Honest scope

  - No new CLI verb (`elsereno sandbox introspect` is
    vNext — needs cobra plumbing + offensive build tag
    handling on the verb).
  - No structured-log integration (the Reason field is
    free-text; structured `audit.sandbox.applied` event
    type is vNext).
  - No Linux-side equivalent (seccomp-bpf programs are
    binary blobs; introspection there means dumping
    cBPF instructions which has a different shape).
