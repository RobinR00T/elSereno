# Snapshot — v2.57.0: OpenAPI top-level examples

Single-chunk cycle. v2.54 backfilled path docs; v2.57 adds
`example:` blocks at the schema component level so Swagger
UI / Stoplight / openapi-generator render concrete sample
payloads instead of placeholders.

## Added top-level examples

  - **ScanSchedule** — full response sample with id, name,
    template, interval, operator, timestamps, retention, tags.
  - **Job** — full response sample including state,
    timestamps, plugins, stats, findings_by_plugin,
    triggered_by_schedule_id.
  - **CreateScheduleRequest** — full request sample with
    template+plugins, cron + timezone, tags.

## Per-field examples

ScanSchedule + Job: each field that previously had no
`example` got one (operator, timezone, interval, etc.).
Helps consumers reading per-field docs.

## docs/openapi.yaml

Regenerated: 774 → 851 lines (+77; the new examples).
`grep "^      example:"` now finds 3 top-level component
examples (previously 0).

## Honest scope

  - UpdateScheduleRequest / CloneScheduleRequest /
    ScheduleAuditEvent / Stats / SubmitRequest didn't get
    top-level examples (the per-field ones suffice; their
    use-cases are obvious extensions of the populated
    schemas).
  - No request examples for non-schedule endpoints
    (/scans, /audit-related POSTs). vNext if operators
    request.
