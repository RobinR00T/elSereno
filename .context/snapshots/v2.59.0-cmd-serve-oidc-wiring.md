# Snapshot — v2.59.0: cmd_serve OIDC Verifier wiring

Single-chunk cycle. Closes v2.38 + v2.40 + v2.43 +
v2.48 carryover. The auth package + RequireRole
middleware + config stanza all existed; v2.59 wires
`elsereno serve` to actually construct the verifier
from cfg.Auth.OIDC + inject through web.Options →
APIV1Deps.

## Plumbing

`internal/web/server.go`:

```go
type Options struct {
    ...
    AuthVerifier *auth.Verifier  // v2.59+
}
```

Forwarded into APIV1Deps.AuthVerifier in NewServer.

`cmd/elsereno/cmd_serve.go`:

```go
if cfg.Auth.OIDC.Enabled() {
    out.AuthVerifier = auth.NewVerifier(
        cfg.Auth.OIDC.Issuer,
        cfg.Auth.OIDC.Audience,
        cfg.Auth.OIDC.JWKSURL,
    )
}
```

Footgun-safe: cfg.Auth.OIDC.Enabled() requires all three
URL fields. Partial config → nil verifier → back-compat
dev mode (X-Operator header). v2.43 already guards this;
v2.59 just consumes the guard.

## Startup log

`elsereno serve` now prints exactly one of:

```
elsereno serve: OIDC enforcement ENABLED (issuer=https://idp aud=elsereno)
```

or

```
elsereno serve: auth in DEV mode (X-Operator header; no OIDC)
```

Operators see at-a-glance which mode the process started
in. Surfaces "thought I configured OIDC but didn't" foot-
guns immediately rather than after the first 401.

## End-to-end chain (now complete)

```
elsereno.yaml: auth.oidc.{issuer, audience, jwks_url}
  ↓ koanf load
config.Config.Auth.OIDC
  ↓ Enabled() check in buildWebOptions
auth.NewVerifier(...) → web.Options.AuthVerifier
  ↓ NewServer
APIV1Deps.AuthVerifier
  ↓ wrapWithRole per route
RequireRole middleware on /api/v1/*
```

## Honest scope

  - No DNS / JWKS reachability check at startup — the
    first request that needs the cache discovers a
    misconfiguration (operator sees 401 + the audit log
    entry has the underlying jwks_url error).
  - No live config reload — operators restart serve to
    re-pick-up config changes (matches existing patterns
    for cfg.Database, cfg.Web).
