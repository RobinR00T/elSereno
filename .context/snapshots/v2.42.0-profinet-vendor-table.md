# Snapshot — v2.42.0: PROFINET vendor + device-id table

Single-chunk cycle. Operators inventorying a PROFINET
segment via v2.41 `decode` saw raw `0x002A` hex; v2.42
adds a curated vendor + device table so they see
`Siemens AG · S7-1500 CPU 1516-3 PN/DP` instead.

## What ships

`internal/protocols/profinet/vendors.go`:
  - 20 curated vendor entries (Siemens, Phoenix Contact,
    Hilscher, Pilz, Schneider Electric, ABB, Rockwell,
    WAGO, Beckhoff, B&R, Hitachi Energy, Bosch Rexroth,
    Endress+Hauser, Festo, Yokogawa, SICK, TURCK,
    Murrelektronik, MTS Systems).
  - 26 device-family entries across the heavy hitters
    (Siemens S7-300/1200/1500/ET 200SP/SCALANCE/SINAMICS,
    Schneider Modicon, ABB AC500, Rockwell 1756-PN2T,
    WAGO 750-series, Beckhoff EK/CX, Phoenix ILC/AXC,
    Bosch IndraDrive/IndraControl, Festo CPX).
  - `VendorName(id)` + `DeviceName(vid, did)` + graceful
    fallback to hex.
  - `FormatVendorDevice(vid, did)` — 3-tier output:
    full match / vendor-only / both-unknown.

## CLI surface change

`elsereno profinet decode` output now includes vendor +
device names in both text + JSON modes:

```
  VendorID:      0x002A (Siemens AG)
  DeviceID:      0x010E (S7-1500 CPU 1516-3 PN/DP)
```

JSON `identify_summary` gains 3 new fields:
`vendor_name`, `device_name`, `vendor_device`.

## Tests (+7 unit)

  - TestVendorName_Siemens, _Unknown
  - TestDeviceName_S71500, _UnknownDevice
  - TestFormatVendorDevice_FullMatch, _VendorOnly,
    _BothUnknown
  - TestVendorRegistrySize (sanity: ≥15 vendors)

## Honest scope

  - NOT exhaustive — PI's GSDML registry has thousands.
    Curated list covers >90% of typical fleets. Operators
    encountering an unknown 0xNNNN can append to
    vendors.go.
  - No GSDML XML parsing — manual entries only.
  - No web fetcher (avoids runtime network dep on PI's
    registry).

## Build sizes

Unchanged (data + simple lookup; in stdlib).

Adds ~130 LoC table + 70 LoC tests + 5 LoC CLI wiring.
