# Snapshot — v2.62.0: `elsereno sandbox` CLI verb (list + introspect)

Single-chunk cycle. Builds the operator-facing surface for
the v2.61 `SchemeFor()` accessor — a read-only,
side-effect-free CLI tree under `elsereno sandbox` so
operators can audit profile policy before firing the
offensive verbs.

## Why now

v2.61 closed the test gap and added `SchemeFor()`, but the
accessor was internal — no CLI path called it, so the
introspection surface was reachable only from Go tests.
v2.62 plumbs it through cobra and makes it visible at
`--help` time. Reachable from every offensive build with
a uniform JSON shape that downstream tooling can pipe to
`jq` regardless of cgo state.

## Verbs

### `elsereno sandbox list`

Prints the 4 profile names from `sandbox.Profiles()` in
declaration order. Works on every offensive build (no
platform branching — Profiles() lives in the always-
compiled `sandbox.go`).

```
$ elsereno sandbox list
exploit
harvest
dial
scan

$ elsereno sandbox list --json
["exploit","harvest","dial","scan"]
```

### `elsereno sandbox introspect [PROFILE] [--all] [--format=text|json]`

Dumps the .sb Scheme for a named profile (or every profile
with `--all`) without applying the sandbox. On the
darwin+cgo build the real Scheme is emitted; on every other
offensive build a sentinel `{"profile": "<name>", "scheme":
""}` row is emitted so downstream `jq` pipelines see a
stable shape rather than crashing on a missing field.

```
$ elsereno sandbox introspect dial
# profile=dial
(version 1)
(deny default (with no-log))
(allow process-fork)
...
(deny network*)
(allow mach-lookup)
(deny process-exec)

$ elsereno sandbox introspect --all --format=json | jq '.[].profile'
"exploit"
"harvest"
"dial"
"scan"
```

Mutual-exclusion + format validation are enforced at the
args layer with clear error messages — `--all` + a
positional arg, or `--format=yaml`, both fail at
`Execute()` before any platform-specific code runs.

## Platform split

Three new files implement the cgo/non-cgo branching:

  - `cmd_sandbox_offensive.go` — `//go:build offensive`.
    Platform-free dispatcher. Calls `schemeForProfile()`.
  - `cmd_sandbox_scheme_darwin_cgo.go` —
    `//go:build offensive && darwin && cgo`.
    Wraps `sandbox.SchemeFor()`.
  - `cmd_sandbox_scheme_other.go` —
    `//go:build offensive && (!darwin || !cgo)`.
    Returns `("", false, nil)`.

Plus a `sandboxIntrospectionAvailable bool` const that lets
the test file branch its assertions across both build
paths without duplicating tests.

## Registration

`cmd_offensive_register.go` extended to include
`root.AddCommand(newSandboxCmd())`. Default-build is
unchanged (no `sandbox` verb at all — the stub-cmds path
doesn't register one because there's no value in a
non-offensive build inspecting offensive-build profiles).

## Test coverage (7 new, both build paths)

  - `TestSandboxList_Text` — 4 profile names, one per line.
  - `TestSandboxList_JSON` — stable JSON array shape.
  - `TestSandboxIntrospect_UnknownProfile` — usage error
    with hint to `sandbox list`.
  - `TestSandboxIntrospect_AllJSON` — `--all` emits 4
    entries; assertions branch on
    `sandboxIntrospectionAvailable`.
  - `TestSandboxIntrospect_AllMutexWithPositional` —
    flag/arg mutual exclusion.
  - `TestSandboxIntrospect_BadFormat` — `--format=yaml`
    rejected.
  - `TestSandboxIntrospect_TextSingle` — text-mode dump
    has `# profile=<n>` header + body.

All 7 pass on both cgo and non-cgo offensive builds.

## INSTALL.md

Updated the per-platform feature matrix to include the new
`elsereno sandbox (list + introspect)` row, calling out
that the full introspection surface is darwin+cgo only and
that the list surface is universal.

## Build sizes

Offensive cgo binary: unchanged at ~35.8 MB (the new code
is ~400 LoC across 4 files; doesn't pull any new deps).
Non-cgo offensive: unchanged.
Default build: unchanged.

## Honest scope

  - No diff/compare verb yet (`elsereno sandbox diff
    A B` would emit the symmetric difference of two
    profile schemes — vNext).
  - No Linux equivalent. Seccomp-bpf programs are binary
    cBPF blobs; dumping them would need a disassembler
    pass. Vague-future work.
  - The sentinel `{"scheme": ""}` row on non-cgo could
    alternatively carry a `{"available": false}` field for
    explicitness; deferred to avoid breaking the shape if
    we later decide to emit something richer.
