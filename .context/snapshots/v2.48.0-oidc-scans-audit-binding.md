# Snapshot — v2.48.0: OIDC binding for /scans + /audit + /findings

Single-chunk cycle. v2.40 bound RequireRole to
/schedules/* only; v2.48 extends to the other 8 read +
mutating endpoints in /api/v1.

## Role assignments

```
Reads (viewer minimum):
  GET /api/v1/findings
  GET /api/v1/findings/diff
  GET /api/v1/runs
  GET /api/v1/triage
  GET /api/v1/audit
  GET /api/v1/audit/cadence
  GET /api/v1/inputs/preview
  GET /api/v1/scans
  GET /api/v1/scans/{id}

Mutations (operator minimum):
  POST /api/v1/scans
  POST /api/v1/scans/bulk
  POST /api/v1/scans/{id}/cancel
```

Total: 12 routes now role-bound (8 new + 19 from v2.40 =
27 of 27 endpoints in /api/v1 now declared).

## Implementation

All routes use the v2.40 `wrapWithRole(v, role, handler)`
helper that's a no-op when AuthVerifier is nil/disabled
(back-compat preserved).

## Honest scope

  - Read endpoints intentionally allow viewer (lowest
    role) — these are the dashboard's main display paths
    + audit-trail browsing; we don't want to break a
    viewer-only console.
  - /stream (SSE) NOT yet wrapped — SSE requires special
    handling around bearer-token-via-query-string for
    EventSource compat. Future cycle.
  - /plugins, /scoring, /health, /openapi.yaml stay
    unbound: public-info endpoints that need to work for
    health-check probes pre-auth.

## Build sizes

Unchanged.

Adds ~10 LoC (wrapping calls + comment).
