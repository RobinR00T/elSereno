# Snapshot — v2.50.0: dashboard theme toggle

Single-chunk cycle. Adds an explicit 3-state theme toggle
(auto/light/dark) to the dashboard header so operators
working under flicker-prone OS-level dark detection (e.g.
shared screens, projectors) can pin a preference.

## States

1. **🌓 auto** (default) — follows OS `prefers-color-scheme`.
2. **☀️ light** — forces light theme regardless of OS.
3. **🌙 dark** — forces dark theme regardless of OS.

Click cycles through the three. Choice persists in
`localStorage["elsereno:theme:v1"]`.

## CSS

Existing `@media (prefers-color-scheme: dark)` rules
remain for auto mode. New explicit overrides via
`body.theme-light` and `body.theme-dark` take precedence:

```css
body.theme-light { --bg: ...; --panel: ...; ... }
body.theme-dark  { --bg: #0b0d10; ...; }
```

`.badge.offensive` got matching explicit overrides so the
red coloration stays correct in both modes.

## JS

  - `currentTheme()` reads from localStorage; falls back
    to "auto".
  - `applyTheme(name)` adds/removes body classes + updates
    the button label.
  - `cycleTheme()` rotates auto→light→dark→auto, persists,
    re-applies.
  - `applyTheme(currentTheme())` runs at script-execution
    time (no FOUC since the toggle is the only
    theme-aware element pre-render; everything else uses
    CSS variables that resolve from body class).
  - `window.cycleTheme` exposed for the onclick.

## Honest scope

  - No system-preference listener — if the OS flips
    dark/light while the page is open under "auto", the
    user has to refresh. Minor; almost no operator
    workflow exercises this.
  - No per-component theme overrides (whole-page swap).

## Build sizes

Unchanged. CSS + JS in the template; zero new bytes in
binaries.

Adds ~60 LoC.
