# Snapshot — v2.38.0: OIDC + roles auth package

Single-chunk cycle. Closes deferred roadmap item — the
largest single architectural addition since v1.50. Adds a
stdlib-only OIDC bearer-token validator with roles-based
access control to the web layer.

## New package: `internal/web/auth/`

### Files

  - **doc.go** — package overview + design invariants.
  - **roles.go** — `Role` enum (Unknown < Viewer < Operator
    < Admin) + `ParseRole` + `HighestRoleFromClaims` +
    `Implies(want)` ordering check.
  - **jwt.go** — stdlib JWT validator (RS256/384/512 +
    ES256/384/512). Manual JOSE parsing via base64 +
    json. **`none` alg rejected unconditionally.**
    Standard claim checks: exp, nbf, iss, aud (+ 60s
    skew). AudClaim helper handles "string or string-array"
    aud shapes.
  - **jwks.go** — TTL-cached JWKS fetcher. Parses RSA +
    EC (P-256/384/521). Force-refresh on
    `ErrJWTUnknownKey` (handles IdP key rotation).
    Default TTL = 15 minutes.
  - **middleware.go** — `Verifier` struct combining cache +
    config. `RequireRole(role, next)` returns an
    http.Handler wrapper. Back-compat: when no JWKS URL
    configured, middleware passes through (preserves v1.58
    X-Operator workflow + entire existing test suite).
    Bearer token extraction from `Authorization` header.
    On valid token: claims + role + operator stashed in
    request ctx via typed accessors.

### Role mapping

Walks 4 claim sources:
  - `roles` (string array)
  - `groups` (LDAP-style)
  - `https://elsereno/roles` (Auth0/Okta namespaced)
  - `https://elsereno/groups`

Highest-rank result wins. Synonyms accepted per `ParseRole`:
admin/administrator/elsereno-admin/root,
operator/scanner/elsereno-operator/scan-operator,
viewer/reader/readonly/elsereno-viewer/read-only.

### Operator identity precedence

`email` > `sub` for audit-chain attribution. When OIDC is
enabled, the audited operator is the JWT identity, not the
X-Operator header.

  - RequireRole_BackCompatMode (no JWKS → pass-through)
  - RequireRole_HappyPath (signed token → ctx-bound role)
  - RequireRole_InsufficientRole (viewer trying admin → 403)
  - RequireRole_MissingToken (no Authorization → 401)

All tests use crypto/rand-generated RSA-2048 keys + a
manually signed RS256 JWT. No third-party JWT lib.

## Wire surface

This cycle adds the package + tests. **Endpoint binding is
NOT yet applied** — that's a follow-up cycle. The middleware
is ready to wrap any http.Handler:

```go
v := auth.NewVerifier("https://idp.example/.well-known/issuer",
                     "elsereno",
                     "https://idp.example/jwks.json")

mux.Handle("/api/v1/schedules",
    v.RequireRole(auth.RoleOperator, schedulesHandler))
```

When `jwksURL` is empty (back-compat dev mode), the
middleware is a no-op and existing X-Operator-based audit
attribution continues.

## Defensive defaults

  - Reject `none` alg unconditionally (CVE-2015-9235 class).
  - Reject tokens with no `exp` claim.
  - Reject HS* (symmetric) algorithms entirely.
  - Issuer match enforced when configured.
  - Audience match enforced when configured.
  - 60s clock skew (configurable per deployment).
  - JWKS body capped at 1 MB (limit reader).

## Honest scope

  - No code/refresh flow — resource-server-only. IdP +
    dashboard UI handle the flow.
  - No token revocation list (RFC 7009) — deferred.
  - No mTLS / DPoP — bearer tokens enough for the OT-network
    use case.
  - Per-endpoint role binding NOT applied in this cycle.
    Package + tests ready; binding lands in a follow-up
    cycle (likely v2.40+).
  - INSTALL.md unchanged (feature is opt-in via config; no
    install delta).
