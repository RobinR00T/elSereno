# Snapshot — v2.49.0: schedule export to iCalendar (.ics)

Single-chunk cycle. Extends v1.97 export endpoint with a
4th format: `?format=ics` returns a VCALENDAR per RFC 5545.
SOC teams import the .ics into shared team calendars to
visualise the scanning schedule alongside other ops events.

## REST

```
GET /api/v1/schedules/export?format=ics
```

Response: `text/calendar; charset=utf-8` +
`Content-Disposition: attachment; filename="elsereno-schedules.ics"`.

## VEVENT shape

```
BEGIN:VEVENT
UID:<schedule-id>@elsereno
DTSTAMP:<now-UTC>
DTSTART:<next-fire-UTC>
DURATION:PT5M
SUMMARY:<schedule.name>
DESCRIPTION:ElSereno scheduled scan · cron=… · input=… · plugins=… · operator=… · tags=…
RRULE:FREQ=HOURLY;INTERVAL=N      (interval schedules only)
STATUS:CONFIRMED / STATUS:CANCELLED (mirrors Enabled)
END:VEVENT
```

## Cadence mapping

  - **Interval** → RRULE FREQ=HOURLY or FREQ=DAILY (best-fit
    by INTERVAL):
    - <3600s → `FREQ=HOURLY;INTERVAL=1` (round up; calendar
      apps don't render finer than hourly).
    - 3600..86400s → `FREQ=HOURLY;INTERVAL=N` (hours).
    - >86400s → `FREQ=DAILY;INTERVAL=N` (days).
  - **Cron** → DESCRIPTION-only (`cron=0 2 * * *`). iCalendar
    lacks a native cron RRULE; clients display opaque text.
  - **Disabled** → `STATUS:CANCELLED` so calendar UI greys
    them out.

## Escaping

`icsEscape` handles RFC 5545 §3.3.11: backslash, newline,
comma, semicolon. Line endings are CRLF per spec.

    interval emits RRULE, cron lands in DESCRIPTION.
  - TestExportSchedules_ICSEmpty: empty store still renders

## Honest scope

  - One-way export only. We don't re-import .ics back into
    schedules (no operator request for that yet).
  - DURATION:PT5M is a static placeholder — actual scan
    duration varies per fleet. Operators wanting accurate
    blocks can adjust client-side.
  - No timezone-aware DTSTART for cron-with-timezone
    schedules (we emit UTC; cron RRULE deferred).
  - INSTALL.md unchanged.
