# Siemens S7comm (TPKT/COTP)

## TL;DR
ElSereno's `s7` plugin sends a minimal read-only probe on port 102/tcp
and classifies the response. Full REPL + per-field decoding land
alongside the generic REPL framework; write operations stay behind
`-tags offensive` (F5).

## Spec references
- TPKT RFC 1006 + ITU-T X.224 class 0 + Siemens S7 comm

## Wire format (summary)
See `internal/protocols/s7/wire/` for the from-scratch parser.

## Fingerprint strategy
COTP Connection Request with TSAPs 0x0100 / 0x0102; a COTP Connection
Confirm scores as S7 (capability 30 to 70), a Disconnect Request or
anything else does not. No Setup Communication and no SZL read in this
plugin (those are `s7 probe` / the opt-in `s7-exposure`); no
vendor/product hint is recorded.

## Read operations (default build)
- `probe`: what `scan` invokes.

## Write / dial operations (offensive build tag)
Deferred to F5.

## REPL commands (planned F4 chunk 2)
- See the generic REPL framework.

## Proxy hooks
Default build: write-ban handler. Each TPKT/COTP/S7 frame is
classified; writes and unknown functions get an S7 AckData error
(class 0x85) and never reach the PLC. Offensive build: per-function
gate (`--s7-fc`).

## Scoring contribution
See `internal/protocols/s7/s7.go` for the factor defaults.
Generic pattern: protocol_risk 80-90 (ICS control plane),
auth_state 80-95 (most have no native auth), impact_class 60-90
depending on the physical process affected.
