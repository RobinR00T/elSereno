# IEC 60870-5-104

## TL;DR
ElSereno's `iec104` plugin sends a minimal read-only probe on port 2404/tcp
and classifies the response. Full REPL + per-field decoding land
alongside the generic REPL framework; write operations stay behind
`-tags offensive` (F5).

## Spec references
- IEC 60870-5-104 (power SCADA)

## Wire format (summary)
See `internal/protocols/iec104/wire/` for the from-scratch parser.

## Fingerprint strategy
TESTFR act (`68 04 43 00 00 00`); a U-format or S-format reply
confirms IEC 104. No STARTDT is sent, so the probe does not tell
whether the server would accept commands; no vendor/product hint is
recorded (IEC 104 carries none at this layer).

## Read operations (default build)
- `probe`: what `scan` invokes.

## Write / dial operations (offensive build tag)
Deferred to F5.

## REPL commands (planned F4 chunk 2)
- See the generic REPL framework.

## Proxy hooks
Default build: write-ban handler. I-format APDUs (the only frames
carrying ASDUs, including control commands) are answered with STOPDT
act; S- and U-format frames forward. The ASDU-aware gate in
`offensive/write/iec104` is not wired to `proxy listen` (orphan
package; open decision in TODO-vNext).

See `internal/protocols/iec104/iec104.go` for the factor defaults.
Generic pattern: protocol_risk 80-90 (ICS control plane),
auth_state 80-95 (most have no native auth), impact_class 60-90
depending on the physical process affected.
