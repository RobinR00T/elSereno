# TriStation (Triconex / Schneider SIS)

## TL;DR
`tristation` is an opt-in, read-only probe for Triconex safety
instrumented systems speaking the TriStation protocol over UDP 1502.
It has two modes, chosen by exactly one of `--active`/`--passive`:
active does a CONNECT/classify/DISCONNECT handshake (plus an optional
CP status read with `--status`); passive reads a pcap/pcapng and
classifies TriStation datagrams off the wire. A hit scores critical:
TriStation is the protocol TRITON/TRISIS abused, and a SIS exposed on
the network is a safety hazard, not just an info leak.

## Spec references
- TriStation UDP framing reverse-engineered by Nozomi/Mandiant around
  the 2017 TRITON incident; `tricotools` and `nse` community work.
- No official public spec; wire details below are from captures and
  the public TRITON write-ups.

## Wire format (summary)
See `internal/protocols/tristation/wire/`. A datagram is a TCM header
(opcode, channel, length, all uint16 little-endian; `tcmHeaderLen=4`)
followed by a TS header (`tsHeaderLen=10`) and a payload, closed by a
CRC-16/ARC (poly 0xA001, little-endian). CONNECT is TCM opcode 1,
DISCONNECT opcode 3. The CP status response is command 108; fields are
read at fixed offsets from the datagram start: key switch @21,
run state @22, firmware minor @72 / major @74, build timestamp @76,
project name @80 (10 bytes).

## Fingerprint strategy
Active: send CONNECT, a well-formed TS response with a valid CRC scores
as TriStation; a malformed length, a bad CRC, or an echo of our own
bytes (`netutil.IsEcho`) does not. We always DISCONNECT and never send
a command frame. Passive: a datagram on UDP 1502 that parses as a TCM+TS
frame with a valid CRC is classified; `Analyse()` scores the session.

## Scoring factors
protocol_risk 95, impact_class 95 (safety system), capability 80 when a
CP status read succeeds (we learned key switch / run state / project),
lower when only the handshake classified. No auth on the protocol, so
auth_state reflects "none required".

## Safety / read-only posture
UDP, fail-closed proxy. The probe never writes: active mode only
CONNECTs, reads status and DISCONNECTs. No command that changes program
state is built (that would be an offensive-build decision, not in
scope). `--status` is still a read.

## Validation
Wire parser + CRC validated against a synthetic capture
(`examples/captures/tristation-demo.pcap`, generated by
`examples/captures/gen/main.go`, 192.0.2.x, project DEMO-SIS). No public
real capture of a full TriStation session was found; the synthetic one
exercises the parser end to end and the passive mode in EXAMPLES §12.
Fuzz test on the wire parser.
